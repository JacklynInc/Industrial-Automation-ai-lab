# Industrial Monitoring Platform

> **Stage 2 — MONITOR**  
> The second stage of the **Industrial Automation AI Lab**: extending the automated production environment into machine-condition monitoring and Industrial IoT.

**Portfolio journey:** [01 — AUTOMATE](../Project-01-automated-production-cell) → **02 — MONITOR** → **03 — PREDICT (coming soon)**


A Python-based industrial monitoring system that simulates machine
sensor data, processes measurements, stores industrial time-series data,
visualizes machine performance, and generates automated alerts.

## Project Overview

This project demonstrates a simplified Industrial IoT monitoring
architecture.

The system monitors:

-   Temperature
-   Vibration
-   Electrical current
-   Machine operating status

Measurements are generated by a simulated industrial motor and
transmitted using MQTT. Python processes the data and classifies machine
health as `NORMAL`, `WARNING`, or `CRITICAL`.

## Machine Health Classification

  Status     Condition
  ---------- ------------------------------------------
  NORMAL     All measurements within normal limits
  WARNING    One or more warning thresholds exceeded
  CRITICAL   One or more critical thresholds exceeded

### Warning Thresholds

  Parameter           Warning
  ------------- -------------
  Temperature        \> 70 °C
  Vibration       \> 2.5 mm/s
  Current            \> 7.5 A

### Critical Thresholds

  Parameter          Critical
  ------------- -------------
  Temperature        \> 80 °C
  Vibration       \> 3.5 mm/s
  Current              \> 9 A

## How It Works

1.  The machine simulator generates sensor measurements.
2.  Measurements are published through MQTT.
3.  The Python monitoring service receives the measurements.
4.  The processing layer evaluates the sensor values against defined
    thresholds.
5.  Each measurement is classified as `NORMAL`, `WARNING`, or
    `CRITICAL`.
6.  Measurements are stored in SQLite and InfluxDB.
7.  Grafana displays the time-series measurements.
8.  Warning and critical conditions trigger automated Telegram alerts
    through n8n.

## Running the System

### 1. Start InfluxDB

Start the InfluxDB server and keep the terminal running.

### 2. Start Mosquitto MQTT Broker

Start the Mosquitto MQTT broker and keep the terminal running.

### 3. Start the Monitoring Service

Start the Python MQTT monitoring service and keep the terminal running.

### 4. Start the Machine Simulator

Start the machine simulator in another terminal.

The simulator generates sensor measurements and publishes them through
MQTT.

## Monitoring

The platform uses Grafana to visualize real-time machine data.

The dashboard monitors:

-   Motor temperature
-   Motor vibration
-   Motor current

Thresholds are displayed on the Grafana panels to help identify abnormal
operating conditions.

## Alerting

The platform generates automated alerts when machine measurements exceed
defined thresholds.

Warning and critical conditions are sent through n8n and delivered to
Telegram.

### Alert Levels

-   **WARNING** --- A warning threshold has been exceeded.
-   **CRITICAL** --- A critical threshold has been exceeded.

### Example Critical Alert

**Machine:** MOTOR_01\
**Status:** CRITICAL\
**Temperature:** 85 °C\
**Vibration:** 4 mm/s\
**Current:** 10 A

Warnings:

-   CRITICAL_TEMPERATURE
-   CRITICAL_VIBRATION
-   CRITICAL_CURRENT
